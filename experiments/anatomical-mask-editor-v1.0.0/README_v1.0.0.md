# Anatomical Mask Editor v1.0.0

Самостоятельный Tkinter-редактор 14 анатомических групп. Исходные DensePose/Flood
Fill эксперименты и Godot не изменяются. Нейросети, сервер и новые зависимости
не нужны. Tkinter/NumPy/Pillow проверены в существующем лёгком окружении проекта.

## Запуск

Из корня репозитория, одной командой PowerShell:

```powershell
./experiments/anatomical-mask-editor-v1.0.0/run.ps1
```

Терминал остаётся занят до закрытия окна; ошибки запуска видны в нём.
Не закрывайте терминал, пока работает редактор. Рабочая версия использует
`edits/`, `exports/`, `review-status.json` и `REVIEW_v1.0.0.md` внутри этого каталога.

```powershell
./experiments/anatomical-mask-editor-v1.0.0/run.ps1 test
./experiments/anatomical-mask-editor-v1.0.0/run.ps1 acceptance
```

Последняя команда проверяет реальные сценарии на копиях под `cache/` и экспортирует
240 тестовых кадров. Эти автоматически созданные правки не являются настоящими
анатомическими исправлениями и не попадают в пользовательские `edits/`.

## Навигация и просмотр

- Слева — 8 поз и все 6 направлений. Только 32 независимых сочетания имеют свои
  правки; `[M]` обозначает зеркальный просмотр. При попытке изменить зеркало
  предлагается перейти к исходному SW/NW. Анатомические L/R ID не переставляются.
- Колесо — масштаб 4/8/16/32; правая или средняя кнопка с перетаскиванием — панорама.
  Center возвращает спрайт в центр. Все масштабы используют Nearest Neighbor;
  при большом масштабе увеличивается только видимая часть изображения.
- Texture / Mask / Grid, Skin 0..4 и Opacity управляют только отображением.
  Skin не создаёт отдельной разметки. Цвета каждого исходного RGBA сохраняются.
- Corrected / Original DensePose / Seeds переключают текущий результат,
  неизменную исходную карту опор и опоры с ручными изменениями. Внизу — native x/y
  и категория под курсором. Выбор категории справа задаёт владельца, а не кость.
  Рисование из Original DensePose автоматически переключает просмотр на выбранный
  редактируемый слой; исходная карта от этого не меняется.

## Прямые исправления

1. Выберите **Final overrides**, категорию и Pencil размером 1/3/5 исходных пикселей.
   Кисть квадратная, быстрые движения соединяются непрерывной пиксельной линией.
2. Один штрих — одна операция Undo. Ctrl+Z / Ctrl+Y и кнопки Undo / Redo поддерживаются;
   незавершённый штрих сначала фиксируется как одна операция, затем отменяется.
   История сохраняется при переходах между случаями в пределах текущего запуска.
3. Eyedropper выбирает категорию текущей исправленной карты. Неизвестное значение 0
   не становится рисуемой категорией.
4. Region fill выделяет четырёхсвязную область одинакового текущего владельца.
   Перед применением область подсвечивается и показывается число пикселей.
   Подтверждение требуется всегда, крупные области дополнительно помечаются.
   Регион определяется по Corrected, независимо от текущего просмотра; preview
   временно показывает именно эту карту. Целевой слой остаётся выбранным оператором.
5. Polygon: последовательно щёлкните минимум три вершины, затем Assign polygon.
   Последняя вершина автоматически соединяется с первой при применении.
   Polygon limits region fill ограничивает следующую связанную заливку полигоном.
   Clear polygon / Esc очищает только выделение.

Все операции ограничены `alpha > 0`. Ни текстура, ни исторические карты не меняются.

## Исправления опор и повторный Flood Fill

1. Переключитесь на **Seed overrides**. Карандаш ставит опоры выбранной группы.
   Erase seeds или Erase seeds in polygon удаляют опоры, не заменяя их другим владельцем.
2. Нажмите **Preview Flood Fill**. Используется существующий
   `densepose-postprocessing-v1.1.0/flood.py:converge()` без изменения N/E/S/W.
   Вход — исходные sparse-опоры + seed overrides, никогда не полностью заполненная карта.
3. Окно показывает Before / After / Changes и количество изменившихся пикселей.
   Final overrides уже применены поверх результата и сохраняются при пересчёте.
4. Accept recompute принимает результат одной операцией Undo. Cancel preview ничего
   не меняет в предыдущей классификации и оставляет подготовленные seed-правки.
5. Пока есть pending seed changes, Save и Export отказывают с понятным сообщением.
   Нужно принять preview или нажать Discard pending seed changes. Последнее можно отменить Undo.

Reset overrides in polygon удаляет override выбранного слоя и возвращает исходное
поведение этого слоя. Это отличается от seed-значения 0, которое явно удаляет опору.

## Сохранение и надёжность

Save edits / Ctrl+S сохраняет два независимых signed int16 слоя:

- `-1`: ручного назначения нет;
- seed `0`: исходная опора удалена;
- `1..14`: принудительно назначенная анатомическая группа.

Final overrides не используют 0: для снятия финальной правки служит Reset overrides.
Сохранённый результат восстанавливается как `Original + Seed -> converge + Final`.
Без правок результат побитово совпадает с v1.1.0 для всех 32 независимых карт.

В `edits/<pose>/<direction>/` есть `manual-overrides.npz` и `metadata.json`.
Сохранение создаёт небольшой неизменяемый архив в `history/`, затем атомарно публикует
metadata с его checksum. Этот manifest — commit point; именованный NPZ — удобная
текущая копия. При переносе правок переносите всю папку, включая history.
Журнал статусов восстанавливается из committed metadata после прерванной записи.
Не редактируйте управляемые NPZ/metadata/status-файлы вручную.

Подпись включает исходные массивы, RGBA всех skin-вариантов, baseline, инвентаризацию,
палитру и точный исходник алгоритма. Изменённые исходники или повреждённый архив
не применяются молча. Исходные файлы не перезаписываются. Счётчик manual pixels
показывает число уникальных пикселей с явным override, а не число пикселей,
перераспределённых последующим Flood Fill.

## Каталог проверки

В журнале ровно 32 записи. Четыре статуса процесса: Not reviewed, Needs correction,
Corrected, Accepted; дополнительный Needs review — начальный приоритетный флаг
для семи случаев из задания. Остальные не считаются правильными автоматически.
Accepted ставит оператор явно. Комментарий и статус сохраняются кнопкой Save.
Next unreviewed переходит к следующему случаю без Corrected/Accepted.
Markdown REVIEW генерируется из машинного журнала, комментарии вводятся в приложении.

## Экспорт

**Export Corrected Masks** создаёт новый уникальный каталог `exports/<id>/`:
240 наборов `owners-final.npy`, цветного `owners-final.png`, `overlay-final.png`
и 14 отдельных бинарных масок. Численная NPY — источник ID, PNG — визуализация.
Экспорт включает текущие несохранённые финальные изменения; Save нужен отдельно
для сохранения слоёв правок. Остальные случаи берутся из committed edits.

Проверяются размеры, alpha, пять skin-геометрий, зеркала и исходные хеши. Сообщение
и metadata явно указывают число неизвестных пикселей. Только набор с metadata
`status=complete` считается завершённым. Hands и Feet остаются отдельными группами;
никакого автоматического импорта или преобразования в 12 Bone2D нет.

## Проверки интерфейса

Окно действительно запущено; через Windows Computer Use проверены выбор Head,
рисование и отмена одного штриха кнопкой Undo. После обнаружения проблемы
Ctrl+Z в текущей раскладке обработка заменена на Windows virtual-key dispatch
и проверена headless-тестом. Пользователь остановил Computer Use физической Esc;
последующие действия в окне, включая повторную проверку горячих клавиш после
исправления, не выполнялись. Панорама/масштаб, polygon/region dialogs, preview,
сохранение и экспорт кнопками требуют дополнительной ручной проверки UI.
Их вычислительные компоненты, сохранение и полный экспорт проверены отдельно.

Тестовое окно, оставленное открытым, использует cache/ui-smoke и старый уже
загруженный код; для проверки последней версии перезапустите указанной командой.
Если в тестовом окне есть нужные несохранённые правки, сначала сохраните их кнопкой
Save edits: они останутся в cache/ui-smoke/edits и не переносятся автоматически.
Ни один тестовый набор не импортируется в пользовательские edits автоматически.
