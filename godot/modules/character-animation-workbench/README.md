# Sprite Animation Workbench

## v1.1: skeletal mesh deformation

Основной стенд v1.1: **`skeletal-animation-workbench.tscn`**.
В нём цельные изображения деформируются через Polygon2D и общий Skeleton2D.
Подробная инструкция по костям, UV и весам: [SKELETAL-WORKFLOW.md](SKELETAL-WORKFLOW.md).
Результаты и ограничения проверки: [SKELETAL-ACCEPTANCE.md](SKELETAL-ACCEPTANCE.md).
Сцена `tests/deformation-proof.tscn` запускает минимальный пример одного цельного тела.

Ниже сохранена инструкция исходной версии v1.0 с жёсткими слоями. Её сцена
и клипы оставлены для сравнения; они не являются скелетным ригом v1.1.

Отдельный стенд ключевой анимации модульного персонажа. Откройте
`character-animation-workbench.tscn` в существующем Godot-проекте.
Персонаж виден сразу в 2D-редакторе. F6 запускает панель предпросмотра.
Главная сцена проекта не меняется.

## Быстрый старт

1. Выберите корень сцены. В Inspector задайте `Outfit`, `Source Pose`,
   `Source Direction`, при необходимости `Preview Zoom`.
2. Выберите `AnimationPlayer`. В нижней панели Animation выберите
   `idle_breathe` или `weapon_swing`, проиграйте или передвиньте курсор времени.
3. Для нового клипа используйте Animation > New, задайте имя и длительность.
4. Выберите `Preview/Mirror/BodyMotion`, его `HeadMotion` или нужный
   `...Base/PivotOrigin/MotionPivot`. Меняйте position, rotation, scale и
   ставьте ключи штатной кнопкой ключа в Inspector/2D-панели.
5. Передвиньте курсор времени, измените позу контроллера, поставьте второй ключ.
   Interpolation и easing задаются в штатном редакторе трека.
6. Сохраните сцену и изменённые внешние анимационные ресурсы. Для отдельного
   нового `.tres` используйте Manage Animations / Save As. Повторно откройте
   сцену и проверьте клип.

Редактор AnimationPlayer является единственной timeline: там доступны
произвольное время, длительность, цикл, удаление и изменение ключей.
Панель F6 содержит только выбор источника/клипа, Play, Stop / RESET,
скорость, масштаб и сетку. Перед сменой источника движение останавливается
и возвращается в нейтральное состояние.

## Откуда берётся композиция

`source-adapter.gd` читает `PreviewOrigin/CharacterSpriteEntity` из
сохранённой `res://modules/character-sprite-tool/character-sprite-tool.tscn`.
Импорт выполняется отдельным обычным процессом Godot, в котором старый
компоновщик работает штатно. Сцена-источник инстанцируется с уже объявленным
деревом узлов; новые узлы программно не конструируются.

`source-settings.tres` содержит именованные наборы **только переопределений
экспортированных свойств источника**. Пути PNG, кадры вариантов и таблицы
подгонки берутся у существующего компоновщика. Примеры:

- `Saved source`: сохранённая исходная композиция без переопределений.
- `Blue shirt`: та же композиция с синей рубашкой.
- `Cutlass`: та же композиция с левой саблей; исходная поза idle/south
  действительно содержит этот вариант оружия. Это стартовый комплект демо.
- `Full layers`: фронтальный комплект с дополнительной одеждой, деталями лица,
  треуголкой, повязками и вторым оружием; служит также полной тестовой композицией.

После изменения сохранённого источника или `source-settings.tres` нажмите
`Reimport saved source` в Inspector корня либо выполните из корня репозитория:

```powershell
./godot/modules/character-animation-workbench/run.ps1 import
```

Сохраните настройки **до** импорта. `base-catalog.tres` содержит 192 снимка:
четыре комплекта, восемь исходных поз, шесть направлений. Каталог является
воспроизводным результатом импорта. В нём сохранены текстуры/кадры,
трансформы, видимость, зеркальность, цвета и порядок слоёв. При повторном
открытии 2D-редактор читает каталог, не исполняя старый runtime-скрипт.
Новые комплекты подхватываются и переключателем, и Inspector после импорта.

**Ограничение исходного инструмента:** его изменения во время запуска
автоматически на диск не записываются. Новый стенд не может прочитать
несохранённое состояние другого процесса. Перенесите нужные экспортированные
значения из Remote Inspector в сохранённую исходную сцену либо в явные
переопределения набора; это отдельное действие пользователя. Стенд не выдаёт
фабричные значения за несохранённую подгонку. Изменение сохранённой сцены
после импорта отмечается предупреждением.

## Узлы и pivot

```text
Preview                         масштаб просмотра
  Mirror                        единственная точка отражения
    BodyMotion                  корпус и одежда
      BodyBase, BootsBase, ...
      HeadMotion                лицо, волосы, головные уборы
        ...Base
    WeaponBase                  независимое оружие
    WeaponSecondaryBase

Каждый Base:
  PivotOrigin                   положение центра вращения
    MotionPivot                 анимируемые position / rotation / scale
      CounterPivot              компенсация положения pivot
        Visual                  Sprite2D
```

`Base` получает только подгонку источника. Ключи ставятся на `MotionPivot`
и групповые `BodyMotion`/`HeadMotion`. Не анимируйте Base или Mirror.
В Inspector Base есть отдельный `Pivot Offset`: меняйте его, чтобы задать
точку вращения. Компенсация сохраняет совпадение изображения в нейтральной
позе; смещение базы не меняется. Сохраняйте pivot вместе со сценой.

Порядок обхода видимых слоёв совпадает с исходным, включая случаи равных z.
`Visual.z_as_relative = false` сохраняет исходный z при группировке.
Скрытие `Visual` или контроллера в новой сцене позволяет временно убрать
деталь, не меняя источник. Отсутствующие/отключённые слои перечисляются
в диагностике; скрытые слои не сохраняют старую картинку другой позы.
Неподдерживаемое оружие остаётся отсутствующим с объяснением причины.

При необходимости добавляйте дискретные треки texture/frame/visible/z_index
на Visual штатным редактором, с режимом Discrete и ступенчатой интерполяцией.
Для них добавляйте соответствующий RESET; тело и одежда не превращаются
автоматически в отдельные руки и ноги. Это анимация существующих модулей,
без морфинга растров и без дорисовывания промежуточных изображений.

## Клипы и направления

Внешняя `animations/demo-library.tres` подключена к AnimationPlayer.
Она ссылается на настоящие `Animation`-ресурсы:

- `idle_breathe.tres`: цикл 2 секунды, движение/масштаб корпуса и поворот головы.
- `weapon_swing.tres`: 0.9 секунды, несколько ключей оружия, корпуса и головы.
- `reset.tres`: нейтральные position/rotation/scale всех объявленных контроллеров.

Клипы адресуют стабильные контроллеры, поэтому смена совместимой одежды
не меняет ключи. Если слой недоступен, его Base скрыт и это видно в диагностике.
Новый клип начинает работу с RESET; новые дискретные свойства включайте
в RESET самостоятельно штатным редактором.

Для восточных диагоналей компоновщик уже задаёт flip_h. Адаптер сохраняет
его фактический результат. При применении снимка позиция и угол Base
нормализуются, а flip_h визуала компенсируется. Затем **только Mirror**
отражает весь риг: изображение совпадает с исходным, движение по X и
направление вращения отражаются один раз. Никакой подмены левого/правого
оружия нет. Различающиеся сохранённые сдвиги восточного направления сохраняются.

Демонстрационные клипы общие. Независимые авторские варианты south, north,
south_west и north_west можно создавать как отдельные клипы/библиотеки
AnimationPlayer и выбирать штатно. Для south_east выбирайте соответствующий
south_west-клип, для north_east — north_west; отражение выполняет риг.
Автоматического выбора боевого клипа для каждого направления в этой версии нет.

## Проверки

```powershell
./godot/modules/character-animation-workbench/run.ps1 test
./godot/modules/character-animation-workbench/run.ps1 visual-test
./godot/modules/character-animation-workbench/run.ps1 smoke
./godot/modules/character-animation-workbench/run.ps1 source
./godot/modules/character-animation-workbench/run.ps1 parse
```

`GODOT_BIN` переопределяет путь движка. `smoke` — короткая проверка запуска,
не интерактивный launcher; для работы используйте F6. Журналы находятся в
`tmp/animation-workbench`. Полная приёмка и известные внешние ошибки
описаны в `ACCEPTANCE.md`.
