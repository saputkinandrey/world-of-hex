# See-through × World of Hex: эксперимент на RTX 3060 Laptop

Это **не** изменение производственного рига. Инструмент `prepare_seethrough_probe.py` только читает оригинальные idle-атласы и существующие ownership-маски, создаёт тестовые входы для See-through и метаданные обратного преобразования координат. Никакие production PNG, TSCN и анимации не изменяются.

## Оборудование и ограничения

Наиболее распространённая RTX 3060 Laptop имеет **6 ГБ VRAM**, но сначала проверьте:

```powershell
nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv,noheader
```

Официальный See-through документирует ~8 ГБ для NF4 на 1280 px, поэтому обычную сборку на 6 ГБ **не** запускать. Для первого теста используйте 512 px, NF4 + CPU offload. Наличие 6 ГБ не гарантирует успешный запуск всех комбинаций CUDA/драйверов. Если происходит OOM: закройте GPU-приложения, уменьшите разрешение, используйте `Blockswap`.

## 1. Подготовить тестовые изображения

Распакуйте этот каталог в корень клона `world-of-hex`, затем откройте PowerShell в корне репозитория:

```powershell
py -3 -m pip install Pillow
py -3 .\seethrough-probe\prepare_seethrough_probe.py --repo .
```

При другом расположении папки укажите полный путь к скрипту и `--repo` на корень своего клона.

Артефакты будут в:

`tmp/animation-workbench/seethrough-probe/`

Создадутся оригинальные S/SW-фреймы, исходные ownership-маски, варианты 512/768 px (nearest и bicubic), а также `manifest.json` с SHA-256 и координатными преобразованиями.

Начните с **`model-inputs/south-west-bicubic-512.png`**. Сравните затем с `south-west-nearest-512.png`: модель обучалась не на пиксель-арте, поэтому нельзя заранее объявлять один метод масштабирования лучшим. До доказательства качества *никакая* интерполяция не должна затрагивать production sprite.

## 2. Запустить See-through локально

Оригинал: https://github.com/shitagaki-lab/see-through

Удобный, но **неофициальный** Windows-wrapper с CPU offload и WebUI:
https://github.com/SuperFurias/see-through-windows

Клонируйте wrapper **в отдельный каталог**, не внутрь игрового репозитория:

```powershell
git clone https://github.com/SuperFurias/see-through-windows.git
cd see-through-windows
.\install_seethrough.bat
.\run_seethrough_webui.bat
```

Wrapper сам скачивает официальный See-through, установщик и зависимости. Перед запуском рекомендуется ознакомиться с `.bat`-скриптами; это сторонняя обёртка, а не официальный инсталлятор. Для моделей/зависимостей нужно ориентировочно **30 ГБ** свободного дискового пространства.

В интерфейсе по адресу `http://127.0.0.1:7860`:

- Inference: **NF4 Quantized**.
- Resolution: **512**.
- **CPU Offload: включён**.
- Inference Steps: начните с **20** (значение для пробного запуска, не оптимум качества).
- `Split Left/Right`: включите, если соответствующий переключатель доступен, чтобы хотя бы предложить раздельные конечности.
- Вход: `south-west-bicubic-512.png`.

Сохраните полученный **PSD**, а также, если wrapper позволяет, слои PNG/метаданные. Не заменяйте оригинальную графику сгенерированными текстурами.

После первого успешного запуска прогоните `south-west-nearest-512.png`. Если качественно распознаёт голову, руки и ноги, можно проверить 768 px. Если не распознаёт анатомию ни на одном варианте — это важный **отрицательный результат**: не переписывать ради него маски!

## 3. Подключить именно существующий rig-c/parts

В отдельном tooling-окружении установите Bun (https://bun.sh/) и пакет:

```powershell
bun add -g @rig-c/parts
rig-parts layers "ПОЛНЫЙ_ПУТЬ_К_ПОЛУЧЕННОМУ.psd"
```

Данная команда читает `.psd` непосредственно и выдаёт диагностическое описание слоёв. Далее `rig-parts sheet`, `assemble --propose-plan`, `assemble` и `propose` настраиваются по [официальному циклу](https://github.com/rig-c/parts#the-loop-for-an-agent) после проверки того, что исходное изображение распознано моделью.

**Важно:** наш этап 1 использует собственный короткий препроцессор, а не `rig-parts inputs`, чтобы сохранить простое отображение обратно в координаты Hex. Для полной интеграции агент должен проверить геометрические предположения `rig-parts inputs` и `assemble`, а не подставлять PSD в неподходящий `config.json`.

## 4. Что именно оценивать

Сравнить PSD на двух методах интерполяции с `sources/south-west.png` и `baseline/south-west-owners.png`:

1. Голова отделена от плеча, челюсть не приклеивается к руке.
2. Кисть не включает пиксели корпуса.
3. Левая/правая нога не слиты в один слой.
4. Контур исходного изображения сохраняет правильную анатомическую принадлежность.
5. Какие скрытые зоны были **синтезированы**, а какие видимые пиксели действительно присутствовали в оригинале.

Не оценивать качество только по красивой восстановленной картинке: реконструкция даже с ошибочной собственностью пикселей может совпадать с оригиналом в нейтральной позе. Для следующего этапа нужны независимые вращения костей и визуальные разницы.

Результат этого этапа: 1–2 PSD, 2 скриншота слоёв, `manifest.json`, сведения о GPU/версии драйвера, и заметки о том, какие конечности разделены успешно.

## Статус

Скрипт предобработки прошёл локальную проверку синтаксиса и тест масштабирования на синтетическом изображении. На реальном репозитории и GPU **не запускался** в среде автора этой заготовки: требуется запуск на вашем ноутбуке.
